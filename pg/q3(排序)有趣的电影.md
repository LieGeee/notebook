### 1. 必背核心：SQL 执行顺序 ⛓️

这是写好复杂 SQL 的地基。虽然书写顺序是 `SELECT` 在前，但数据库的内心顺序如下：

| **执行顺序**   | **关键字**       | **数据库的行为**                      |
| ---------- | ------------- | ------------------------------- |
| **1️⃣ 最先** | **FROM**      | 确定去哪张表找数据，并给表起别名。               |
| **2️⃣ 其次** | **JOIN / ON** | 把不同的表拼在一起，形成一张大横表。              |
| **3️⃣ 关键** | **WHERE**     | 进行第一轮过滤（此时还不能用 `SELECT` 里的别名）。  |
| **4️⃣ 核心** | **SELECT**    | 决定最终要展示哪几列，并定义列别名。              |
| **5️⃣ 最后** | **ORDER BY**  | 对最终结果进行排序（此时可以用 `SELECT` 里的别名）。 |
|            |               |                                 |
|            |               |                                 |

### 2. 必背模板：自连接 (Self-Join) 🔍

当题目要求在**同一张表**内比较两个不同角色（如：员工与经理、今天与昨天）时，使用这个“分身术”模板：

- **逻辑口诀**：一张表化为两张表，左右对齐找关联。
    
- **代码结构**：
    
    SQL
    
    ```
    SELECT e.name AS Employee
    FROM Employee e, Employee m        -- e 代表员工分身，m 代表经理分身
    WHERE e.managerId = m.id          -- 对齐：员工的经理 ID 等于经理的个人 ID
      AND e.salary > m.salary;        -- 筛选：员工薪水大于经理薪水
    ```

### 3. 必背语法：细节过滤与排序 🍿

针对“有趣的电影”这类基础筛选题，记住这三个关键点：

- **NULL 处理**：绝对不能用 `= NULL`，必须用 **`IS NULL`** 或 **`IS NOT NULL`**。
    
- **奇偶数判断**：
    
    - 通用：`id % 2 = 1`（奇数）、`id % 2 = 0`（偶数）。
        
    - 函数：`MOD(id, 2) = 1`。
        
- **排序 (Order By)**：
    
    - **`DESC`**：降序（从大到小，如 9.1 $\rightarrow$ 8.9）。
        
    - **`ASC`**：升序（从小到大，默认选项）。
